# Pen Pal: developer notes

Handoff notes for continuing development in a new chat. Read this first, then README.md.

## What this is
A private poetry submission tracker for one poet (Christian, Miami, Windows PC). Formerly "Poetry Tracker"; renamed Pen Pal and turned into a Windows program in v2.0.0 (Nov 2026). He has about 10 poems he's happy with and is working toward a chapbook.

Hard requirements he set:
- Runs on his Windows PC as a proper program (PenPal.exe), not a phone app.
- **Poem text is never stored.** Titles and notes only. Do not add a poem-text field.
- New rules go in `public/logic.js` with tests; check UI changes in a real browser (tests/browser_smoke.py); no em dashes in anything the tool displays (a test scans for them); hand back a zip and, once the repo exists, the GitHub release link.
- Keep dependencies minimal: Python standard library for the server, plain HTML/JS for the page. The only extra is pywebview (plus PyInstaller at build time), bundled inside the exe so he installs nothing.

## Architecture
- `penpal.py`: the desktop entry point. Starts `server.py` in a thread on 127.0.0.1 and shows the page in a pywebview window (Edge WebView2 on Windows). Frameless (Pen Pal's own title bar) unless settings.json says `titleBar: "windows"`. Exposes to the page via `window.pywebview.api`: `save_file` (native Save dialog, used for every download), `open_data_folder`, and window controls `win_minimize`, `win_toggle_max`, `win_is_max`, `win_bounds`, `win_set_bounds`, `win_close`. Frameless WinForms windows have no resize border and a normal maximize covers the taskbar, so: the page draws 5 px edge zones that call `win_set_bounds` while dragging (logical px, min 900x620), and maximize moves/resizes to the monitor work area from `GetMonitorInfoW` (falls back to `window.maximize()`). Drag region is the `.pywebview-drag-region` class (removed while maximized). Sets `server.RESTART_HOOK = window.destroy` and deletes `PenPal.old.exe` at start-up (retrying for 5 minutes).
  - **js_api rule:** pywebview walks every public attribute of the `Api` object, recursing into objects, to build `window.pywebview.api`. Only methods may be public. 2.0.0 to 2.1.0 had `api.window`, which sent the walk through the native WinForms/WebView2 objects from a background thread. `tests/test_desktop.py` enforces this.
  - **Closing rule:** pywebview runs the `closing` handler on the UI thread and waits for it. Never block there or call `evaluate_js` (it waits on the UI thread too: 2.1.0 froze on every close this way). The page calls `set_busy(true/false)` when a save is pending; `closing_handler` cancels the close if busy, waits up to 5 s on another thread, then closes again.
  - **Log:** `pen-pal-log.txt` in the data folder (previous run kept as `.prev.txt`). Gets stderr, `logging` (including pywebview's), uncaught exceptions in any thread, and `faulthandler` traces for native crashes. The server only logs failed requests there, and never bodies. Waits for an in-flight save on close (`window.PenPal.busy()`). Falls back to the browser without pywebview, or with `--browser`. `--check FILE` is a self-test against a throwaway data folder; CI runs it on the built exe.
- `server.py`: standard library only. Serves `public/`, `/api/data` (GET, PUT whole document with `rev`), `/api/settings` (GET/PUT, merges `backupFolder` and `titleBar`), `/api/info` (version, data folder, desktop, frameless, titleBar, canInstall), `/api/update` (GET check, cached 10 min, `?force=1`), `/api/update/status`, PUT `/api/update/download` and `/api/update/apply`.
- `notify.py`: standard library only. Windows notifications for reading-period reminders: registers the AppUserModelID `ThatOneGuyCpr.PenPal` under HKCU (name and icon, no shortcut needed) and a `penpal:` URL protocol that only opens the app (so clicking a notification opens Pen Pal); shows toasts through Windows PowerShell 5.1's WinRT API (XML passed in an environment variable); remembers shown reminders in `reminders-sent.json` next to settings.json (keys `journalId:opens|closes:date`, pruned once the date passes; a failed show is retried later; more than 3 at once become one summary); adds or removes the Task Scheduler task "Pen Pal reminders" (logon + daily 9 AM, StartWhenAvailable, least privilege, runs `PenPal.exe --remind`). `PENPAL_FAKE_NOTIFY=file` records notifications instead of showing them.
- Reminders: which are due is `windowAlerts` in logic.js. The app calls `api.notify(alerts)` at start and every 30 minutes, and `api.sync_reminders(anyBell)` at start and on changes (only the frozen exe on Windows gets a task; it is re-created if the exe moved). `PenPal.exe --remind` reads the data file, exits at once if no bell is on, otherwise opens a hidden window on `remind.html` (logic.js + remind.js), which hands the due reminders to `RemindApi.finish`, then exits with `os._exit` (a lingering run would block the next one). It never writes the data file. Its log is `pen-pal-reminders-log.txt`.
- `updater.py`: standard library only. Reads the latest release from the GitHub API, downloads `PenPal.exe` to `PenPal.new.exe` (URL must start with this repo's releases/download prefix; size, sha256 `digest` from the API, and the `MZ` header are checked), swaps by renaming the running exe to `PenPal.old.exe` (Windows allows renaming a running exe, not deleting it) and moving the new one in, rolls back on failure, relaunches detached, and the new copy removes the old file. `PENPAL_UPDATE_API` / `PENPAL_UPDATE_PREFIX` env vars point it at a fake for tests. Only a frozen exe in a writable folder installs; from source the page links to the releases page. Host must be 127.0.0.1/localhost; PUTs need header `X-Pen-Pal: 1` (the old `X-Poetry-Tracker` is still accepted). `resource_dir()` is `sys._MEIPASS` when frozen (public/ is bundled with `--add-data`); `default_data_dir()` is `./data` from source, else a `data` folder beside the exe if present, else `%APPDATA%\Pen Pal\data`.
- `public/logic.js`: all rules, pure functions, works in browser and Node. **Put new rules here, with tests.**
- `public/app.js`: rendering, dialogs, saving, undo. Template strings with `esc()`. Event delegation via `data-act` / `data-tab`. Sections: desk, find, journals, poems, subs, books, budget, insights, calendar, import, export.
- `public/style.css`: palette from the approved mockup (ink #16202B, airmail red #B8322A, blue #234E8C), light and dark. Fonts bundled in `public/fonts` (Young Serif, Public Sans, IBM Plex Mono; OFL, licenses in fonts/LICENSE.txt). No CDNs.
- `public/directory.json`: the starter journal directory (see below).
- `assets/penpal.ico`: app icon. `start.bat` (runs PenPal.exe if present, else `penpal.py`), `build-exe.bat` (local build). Both CRLF and ASCII.
- `.github/workflows/build.yml`: on push, tests + build + `--check` on windows-latest, uploads the exe as an artifact; when `APP_VERSION` in server.py has no release yet, publishes one (tag v{version}) with PenPal.exe and RELEASE_NOTES.md. Tag pushes from Claude sessions are refused, which is why releases key off the version instead. To ship an update: bump APP_VERSION, rewrite RELEASE_NOTES.md, push to main.

## Data model (normalize functions in logic.js)
- Document: `{ rev, poems[], journals[], submissions[], manuscripts[], entries[], settings }`. Older files load fine; new fields default.
- Poem: `id, title, status (draft|ready|published), publishedWhere, publishedDate, notes, rights{bought, issue, pubDate, exclusiveUntil, reprints yes|no|unknown, revert, credit}`.
- Journal: `id, name, url, opens, closes, repeat (none|yearly), extraWindows[{opens:'MM-DD', closes:'MM-DD'}], alwaysOpen, fee, maxPoems, simSubs, replyDays, pays, reprints, dirId, checked, notes`. Every date question goes through `windowsFrom` / `currentWindow`, which roll yearly templates forward (extra windows too) and treat `alwaysOpen` as open.
- Submission: `id, poemIds[], journalId, sentDate, status, acceptedPoemIds[], withdrawnPoemIds[], responseDate, feePaid, notes, queriedDate, snoozedUntil`.
- Manuscript and Entry: as before (entries: planned|pending|finalist|accepted|rejected|withdrawn).
- Journals have `notify` (the bell). `remindClosed` (default true) lives in server-side settings.json because it is about this PC.
- Settings (in the document): `lastBackupDownload, backupSnoozedUntil, monthlyBudget{'YYYY-MM': amount|null} (each key is a change that holds from that month on; null means none; repeats are tidied away; a 2.0/2.1 `budgets{YYYY}` converts to a twelfth from that January), budgetWarnPct (80), countPlanned (true), theme (system|light|dark), followUpDays (90, 14-365), deskDays (60, 7-180), notifyDays (3, 0-30), checkUpdates (true)`. The title bar choice lives in server-side `settings.json` instead, because the window is created before the page loads.

## Decisions worth knowing
- **Directory:** 22 poetry journals, checked 2026-11-23 against each journal's own guidelines, a few details from publisher-supplied Poets & Writers listings. Blank or "unknown" means not confirmed; never guess a value. Chill Subs, Duotrope and P&W are proprietary, so nothing is copied from them; "Search Chill Subs / Poets & Writers" buttons run a DuckDuckGo site search because neither site documents a search URL. `dirIsStale` warns after 180 days. To grow it: add entries to directory.json (a test validates every entry) and bump `checked`.
- **Follow-ups:** expected reply = median of his own answered submissions to that journal (2+), else the journal's `replyDays`, else 90. After "I followed up", the next reminder is 60 days later; snooze is 30 days.
- **Budget:** monthly, by sent date (planned entries by deadline month). `budgetFor(settings, ym)` finds the change in force; `budgetSummary(data, ym)` is one month, `budgetYear(data, year)` is the chart. `budgetCheck` warns at `budgetWarnPct` and when over; it runs in the submission and entry dialogs and never blocks.
- **History import** (`buildSubImport`): duplicates match on journal name + sent date + set of titles, so re-importing is safe. "Never responded" style statuses import as withdrawn with a note. Unreadable dates stay in notes.
- **Saving:** whole-document PUT with revision counter (409 on stale); atomic writes; daily backups; optional second folder (`pen-pal-latest.json` + dated copies) that never blocks a save; never starts over an unreadable data file.
- Pre-send warnings never block. Plain wording, no em dashes.

## Tests
- Logic: `node --test tests/logic.test.js` (75 tests)
- Server, updater and desktop: `python -m unittest discover -s tests -p "test_*.py"` (56 tests; reminders in test_notify.py; the updater tests run against a local fake of GitHub, including bad fingerprint, wrong size, not-an-exe, foreign URL, swap and rollback)
- Reminders end to end: `python penpal.py --remind-check out.txt` runs the rules in a hidden window against a throwaway data folder and checks which reminders come and that each comes once; on Windows it also checks the notification registration, that Windows accepts the notifications, and creates, reads back and removes the task under a test name. CI runs it against the built exe.
- Real window: `python penpal.py --smoke out.txt [--title-bar windows]` opens the actual pywebview window on a throwaway data folder, drives the title bar controls through the bridge, closes during a pending save, and fails on a hang, a crash or any error in the log. CI runs it on Windows for both title bars against the built exe. On Linux it runs with `pip install PyQt6 PyQt6-WebEngine qtpy` and `PYWEBVIEW_GUI=qt QT_QPA_PLATFORM=offscreen`.
- Browser: `python tests/browser_smoke.py` (113 checks; includes Settings, themes, the update check against a fake GitHub, and the custom title bar driven through a stand-in for the desktop bridge: minimize, maximize/restore, edge resizing, close, Save dialog downloads; needs Playwright + Chrome). Seeds an old-format Poetry Tracker file and covers every section, the budget warning, follow-ups, rights, both importers, backups, the two-window conflict, dark mode, phone width and console errors.
- The one-file PyInstaller build was checked on Linux (bundled public/, `--check` passes, data folder choice correct). **Not yet confirmed on real Windows:** dragging the title bar and edge resizing by hand on scaled displays (CI drives the same calls, not the mouse), the Save dialog bridge, the in-app update swap, SmartScreen behavior, start.bat and build-exe.bat. The first real update test will be 2.1.0 to the next version; 2.0.0 has no updater, so 2.1.0 must be installed by hand once. The GitHub workflow runs the build and self-check on Windows once the repo exists.

## Publishing background he was given (context, not app logic)
Chapbooks run roughly 20 to 40 pages; full-length collections 48 to 100. Many presses like 25 to 50 percent of a manuscript to have appeared in journals. Entry fees of $15 to $25 are typical. Simultaneous submissions are usually allowed. Avoid vanity presses.
